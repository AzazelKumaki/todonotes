# 安卓壳工程 · 打包说明

## 这是什么

手机 App 就是一个**原生的壳子 + 你的网页**。打开 App，里面跑的就是 `prototype/index.html`。

好处：**网页端和手机端功能完全一致** —— 不存在"手机上少了哪个功能"，因为它们是同一个文件。
壳子本身**零第三方依赖**（WebView 是安卓系统自带的），所以 APK 只有几十 KB。

## 怎么打包

**双击 `build-apk.bat`**，等一两分钟，产物会复制到项目根目录：
`待办清单-V0.2.apk`

> 第一次构建会联网下载 Gradle 的依赖（约几十 MB），之后就有缓存了。

## 每次改完网页重新打包

直接再双击一次 `build-apk.bat` —— 它会自动把最新的 `prototype/index.html` 拷进来再打包。

## 壳子干了四件事

| 事 | 为什么必须有 |
|---|---|
| 打开 localStorage 开关 | 你的数据全存在这里，不开的话一关 App 数据就没了 |
| 允许跨域请求 | 不然 AI 解析调不通（服务商接口在别的域名） |
| 把导出文件写进「下载 / 待办清单」 | 手机上点导出要真落到文件夹。用 MediaStore 写，**一个权限都不用申请** |
| 接管返回键 | 先退一层（详情页 → 列表），退不了才双击退出 |

## 版本号

在 `app/build.gradle` 里：`versionCode 2` / `versionName "0.2"`。
App 里「我的 → 检查更新」显示的就是这个版本号。

**升级时两个都要改**：`versionCode` 必须比上一个大（手机靠它判断是不是新版本），`versionName` 写给人看。

## 签名

`daiban.keystore` 是自己签的（口令 `daiban2026`），装在手机上会提示"未知来源"，允许一次就行。

⚠️ **这个文件不能丢**：丢了就没法给 App 出更新包，只能让用户卸载重装（重装会丢本机数据）。建议跟备份文件一起存一份到网盘。

## 已知限制

- 最低支持**安卓 10**（Android 10 以下装不了）。再往下要处理存储权限，麻烦且没必要。
- 手机上检查更新现在是静态提示。要接真的在线更新，得先把 APK 放到一个能访问的网址上（V0.3 再说）。
- 某些 AI 服务商可能不允许从 App 内部跨域调用（CORS）。遇到解析总是降级成本机规则时，换一家服务商试试。
