# V0.3 云同步 · 怎么试（用户视角）

> 一句话：**先在本机把整条链路跑通（不用注册任何账号），顺手了你再决定要不要换成真正的云。**
> 无论用哪种后端，App 的用法完全一样 —— 换后端只是改配置里的两行字。

---

## 一、三分钟在本机试一遍（零注册）

### 第 1 步：启动同步服务器
双击 `tools/start-sync-server.bat`，会弹出一个黑窗口，别关它。看到这样就是好了：

```
服务地址（电脑上这份 App 填） : http://127.0.0.1:8787
服务地址（手机 App 填这个）   : http://192.168.x.x:8787
密钥                         : local-dev-key
```

### 第 2 步：在 App 里填配置
双击打开 `prototype/index.html` → 底部「我的」→ 点最上面那张「☁️ 云同步」卡片 → 填三样：

| 项 | 填什么 |
|---|---|
| 服务地址 | `http://127.0.0.1:8787` |
| 密钥 | `local-dev-key` |
| 同步口令 | 自己起一个（比如 `我的清单2026`） |

点【测试连接】→ 显示"连接成功"→ 点【保存并开启】。

### 第 3 步：看它真的同步了
- 记一条新的待办 → 等 1~2 秒 → 黑窗口里会多一行 `PUT .... ← 15 条待办`
- 「我的」页那张卡会变成 **云同步 · 已连接 · 上次同步 21:35**

### 第 4 步：用第二个"设备"验证
最简单：再开一个浏览器窗口（或换个浏览器）打开同一个 `index.html`，填**一模一样的三样**，
它会自动把云端那份拉下来。你在 A 窗口改，B 窗口过两秒就变了。

> 两台设备的**同步口令必须一样**，不一样就是两个互不相干的空间，互相看不见 —— 这正是"口令决定谁共用一份数据"。

### 第 5 步：手机也能连（可选）
手机和电脑连同一个 WiFi → 手机 App 里服务地址填 `http://192.168.x.x:8787`（黑窗口里给的那个）。
第一次可能弹出 Windows 防火墙，允许即可。

## 二、换成真正的云：Supabase（跨城市也能同步）

本机那个服务器只在你电脑上跑，关机就没了。你已经在 Supabase 建好项目的话，跟着做下面五步。

### 第 1 步：拿到地址和密钥
在 Supabase 后台找这两样（Settings → API / 或项目首页的 Connect 对话框）：

| 要什么 | 长什么样 | 填到 App 哪栏 |
|---|---|---|
| **Project URL** | `https://xxxx.supabase.co` | 服务地址（**末尾别带斜杠**） |
| **Publishable key** | `sb_publishable_…` 开头 | 密钥 |

老项目页面上显示的可能是 `eyJ…` 开头的 **anon key** —— 那个也能用，App 两种都认。

> ⛔ **绝对不要填 `sb_secret_…` / service_role**。它能绕过一切权限限制，而 App 是可以被反编译的 —— 前端没有真正的保险箱。
> 自检脚本发现你填了 secret key 会直接拦下来。

### 第 2 步：建那张表（四段 SQL）

<details><summary>这四段到底在干嘛？点开看大白话版</summary>

把云端想成**一柜子的格子**：

| 段 | SQL | 大白话 |
|---|---|---|
| ① | `create table` | 做一个柜子，每行一个格子。`space_id` = 格子编号（由你的**口令算出来**的 256 位串，口令本身不上传）、`payload` = 格子里装的东西（你的全部数据）、`updated_at` = 最后改动时间 |
| ② | `enable row level security` | **给柜子装总闸**。装上以后默认谁都不让动 —— 这是安全底线。不装这闸，任何人拿到你的 key 就能扫整张表 |
| ③ | `create policy` | 在总闸上开一条规则：允许 App 读写**它自己那一格**。我们的门禁不是账号，而是"**格子编号不可猜**"，跟网盘分享链接一个道理 |
| ④ | `grant ...` | 告诉数据库"允许这两种角色来碰这张表"：`anon` = 没登录的访客（我们没做登录，App 就是以这个身份来的）、`authenticated` = 登录过的 |

**为什么要两道门？** Postgres 检查两件事：

```
请求进来 → ① 授权 GRANT：这个角色能不能碰这张表？ → ② 策略 Policy：能碰哪些行？ → 数据
```

缺任何一道都失败，而且报错长得很像 —— 这就是"表建好了却说没权限"的来源。**第 ④ 段最容易被漏掉。**

</details>

#### 具体怎么点
1. 左侧点 **SQL Editor**（图标是 `>_`）
2. 点 **New query**
3. 粘**一段**进去 → 点右下角绿色 **Run**（或按 `Ctrl + Enter`）
4. 下面出现绿色 **Success. No rows returned** 就是这段成了
5. 四段依次跑完（一次全粘进去跑也行，SQL Editor 认多句）

#### 怎么确认建好了
左侧点 **Table Editor** → 列表里应该出现 **`todo_state`**，点开能看到 5 列：
`space_id` / `payload` / `updated_at` / `device_id` / `app_ver`。

#### 报错怎么办
| 看到 | 意思 | 怎么办 |
|---|---|---|
| `already exists` | 这段已经跑过了 | 不用管，继续下一段 |
| `syntax error` | 复制时少了字符 | 重新复制，注意别漏分号 |
| `permission denied`（建表时） | 极少见 | 确认你是这个项目的所有者 |
左侧 **SQL Editor → New query**，去 App 里点【复制建表脚本】，把内容**一次粘一段**跑完，一共四段：

1. 建表 `todo_state`
2. 打开行级安全
3. 建访问策略
4. **授权**（这段别漏，漏了会报"没权限"，表建了也读写不了）

### 第 3 步：先自检，别急着填 App
在项目目录里跑（把地址和密钥换成你的）：

```bash
node tools/check-supabase.js --base https://xxxx.supabase.co --key sb_publishable_xxx
```

四行全绿才算配好；**红字会直接告诉你缺什么**（表没建 / 缺授权 / 密钥不对 / 地址错），比在 App 里猜快得多。

### 第 4 步：在 App 里填三样
「我的 → ☁️ 云同步」填地址、密钥、同步口令 →【测试连接】→【保存并开启】。

**口令可以沿用你原来那个** —— 换后端相当于换了一个空房间，第一次同步会自动把你本机的数据推上去。

### 第 5 步：第二台设备
一台【导出配置码】→ 另一台【导入配置码】，粘进去自动测连通并开启。

### 两个要记住的
- 免费项目**长期不打开可能会被暂停**，去后台点一下恢复即可；暂停期间 App 照常用，只是不同步。
- 手机 App 连 Supabase 用的是公网 HTTPS 地址，**不要求同一 WiFi**，这点跟本机试用服务器不一样。

## 三、另一台设备怎么配：配置码

一台点【导出配置码】→ 复制那串 `DBSYNC1:...` → 另一台点【导入配置码】粘进去 → 自动测连通并开启。

⚠️ **配置码里含地址、密钥、口令，等于你家钥匙。** 别发群、别存网盘。
另外它是**没有找回通道**的：口令忘了、配置码丢了 = 这份云端数据找不回来（本机数据不受影响）。

## 四、出问题看这里

| 看到什么 | 怎么回事 | 怎么办 |
|---|---|---|
| 请求根本没发出去 | 后端不给跨域许可，或地址填错 | 检查地址；Supabase 默认给，自建的要自己配 |
| 密钥不对 | 粘漏了 / 粘多了空格 | 重新粘，别带空格 |
| 密钥里有中文或全角符号 | HTTP 头放不下中文 | 重新粘贴一遍（正常密钥都是英文数字） |
| 表还没建 | 地址通了但缺那三段 SQL | 去后端跑建表脚本（App 里有【复制建表脚本】） |
| 等太久没回应 | 网络不通 / 服务器没开 | 先确认那个黑窗口还开着 |
| 连的是 `127.0.0.1` / `192.168.x.x` 却连不上 | 浏览器的"本地网络保护"会多问一句，服务端要点头 | 用自带的 `tools/sync-server.js`（已处理）；**换成 Supabase 公网地址就没这一步** |
| 表建了却报"没权限" | 漏了第 4 段授权 | 补跑 `grant select, insert, update, delete on table public.todo_state to anon, authenticated;` |
| 刚建完表就说"表不存在" | Supabase 的接口缓存还没刷新 | 等半分钟重试；或去 **Integrations → Data API** 把 `todo_state` 勾上暴露 |
| 填了 `eyJ…` 却提示密钥不对 | 老式 anon key 被停用了 | 换成页面上新给的 `sb_publishable_…` |

**任何同步失败都不会影响你用 App** —— 数据都在本机，状态栏会告诉你原因，不弹窗、不卡界面。

## 五、这次做了什么 / 没做什么

**做了**：云同步（自动拉推、断网补传、冲突让你选）、同步口令与空间隔离、配置码换设备、状态栏。
**没做**：多设备逐条精细合并（现在是"整包，谁新用谁"）、上传前加密、云端附件、多人协作。

> 冲突规则跟导入备份一个口径：**同一个条目，以最后修改时间更晚的那份为准**。
> 两台设备都改了同一份数据时，App **不会偷偷覆盖**，会弹出来让你选以谁为准。
