| 产出字段 | 识别方式 |
|---|---|
| `imp`（重要） | 正则 `/重要\|关键\|老板\|考核\|必须/` 命中即 `true` |
| `urg`（紧急） | 正则 `/急\|尽快\|马上\|今天必须\|催\|赶紧\|临时/` 命中即 `true` |
| `due`（日期） | `/今天/` → `TODAY`；`/明天/` → `TODAY+1`；`/下周/` → `TODAY+7`；**其余一律不识别** |
| `time`（时分） | 正则 `/(\d{1,2})\s*点/` → 取小时 + `':00'`（**分钟恒为 00**） |
| `dueText` | 展示用文案：`'今天'` / `'明天'` / `'下周'`（可再拼 ` HH:00`）；无结果时为 `'（没听出时间）'` |

| `title`（标题） | **不是语义抽取**：删掉标点符号 `，。！,.!` → 删掉 `明天/今天/下周/之前/前/尽快/马上/记得` → `trim()` → **取前 20 个字符** |

**识别失败的后果**：

| 场景 | 代码行为 |
|---|---|
| 整句没命中任何规则 | `imp=false, urg=false, due='', dueText='（没听出时间）', cat=null`，`title` = 原话去停用词后前 20 字 |

**已确认的时区缺陷（事实）**：

`明天` / `下周` 分支用 `d.toISOString().slice(0,10)`。`new Date('2026-10-15T00:00:00')` 按**本地时间**解析，而 `toISOString()` 输出 **UTC**。在 UTC+8（东八区）下：

| 输入 | 期望 | 实得（实测） |
|---|---|---|
| `明天` | `2026-10-16` | **`2026-10-15`**（= 今天） |
| `下周` | `2026-10-22` | **`2026-10-21`**（= 今天+6） |

**与 PRD 的差距**：PRD FR-001（237 行）要求解析出"标题、完成时间、重要、紧急、归属域、分类"六项，其中**归属域**代码不产出；PRD 5.1 流程要点 1（348 行）要求"传入当前日期时间"，代码传入的是**硬编码常量** `TODAY`（347 行）；PRD 4 要求"AI 只做提取不做推测"，代码连提取都不是，是关键字匹配。

## 9. 附：一句话总览

`prototype/index.html` 是一份 **1317 行、零依赖、零网络、零持久化**的单文件交互原型：
11 个视图 + 7 类弹层，56 个 `data-act` 动作（约 52 个可从界面触发，3 个无入口、1 个不可达），
内置 18 条种子待办 + 2 条种子复盘 + 8 个种子分类；
四象限配色与 PRD 8.5 逐值一致，工作/生活域的配色、圆角、内边距与 PRD 8.6 逐项一致；
AI 解析为正则关键字模拟、复盘为硬编码文案、云同步/备份/导出/背景图/回收站清理均为 UI 占位。
