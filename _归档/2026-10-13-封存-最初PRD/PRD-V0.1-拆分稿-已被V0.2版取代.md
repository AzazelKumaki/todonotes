## 0. 三句话讲清现在是什么

1. **V0.1 是一个能真用起来的本地待办 App**：记一条 → 关掉再打开还在 → 能改能勾 → 日历能翻月。
2. **AI 解析是本地规则版**（关键词 + 日期解析），**不联网、不要 API Key**；解析不准不阻塞记录，不准就进收件箱手动归类。
3. **复盘是空壳**（保留位置，不放假内容），**云同步 / APK / 备份 / 循环安排都不在 M1 范围内**。

## 2. 模块拆分（M1 交付规格）

### 模块 E · 数据存储（FR-025，地基，最先做）

| 验收 | 内容 |
|---|---|
| 1 | 任意一次改（记一笔 / 改字段 / 勾完成 / 删除 / 改分类 / 改设置）后，**关掉浏览器再打开，数据完全一致** |
| 2 | 存：待办 + 分类 + 设置（**不含 API Key**） |
| 3 | 用浏览器本地库（localStorage），**不申请任何系统权限** |
| 4 | **首次启动**写入预置 8 个分类（工作：项目推进/会议沟通/报表材料/临时插单；生活：家人/健康运动/缴费账单/采购）；之后以用户数据为准，**不得每次启动重置** |
| 5 | 存储层**单独封装**（见 §5 接口契约），换 IndexedDB 或加云同步只改这一处 |
| 6 | 1000 条待办打开 ≤ 1 秒 |

### 模块 A · 记录

**FR-001 一句话录入 + 规则版解析**
1. 输入一句大白话 → 点【✦ 解析】→ 产出 6 项：标题 / 完成时间 / 重要 / 紧急 / 归属域 / 分类
2. **重要 / 紧急：提到才算"是"，没提到 = "否"** —— 绝不擅自判定（硬规则）
3. 日期支持：今天 / 明天 / 后天 / 下周 / 下个月；时间支持 `3点`、`下午3点`、`9点半`、`4点45`
4. 分类只能从**当前域已有的分类**里挑，不自造
5. **M1 用本地规则实现**，不联网、不要 Key

**FR-002 解析面板**
1. 面板在输入框下方展开（非全屏弹窗），共 **5 行**：标题 / 完成时间 / **轻重缓急** / 归属 / 分类
2. **整行可点**即改，不显示「改」字
3. **「轻重缓急」是一个四象限选择器，1 次点击即选中**（马上做 / 计划做 / 快速处理 / 有空再说 / 未判断）
4. 面板有【保存】与【再改改】

**FR-003 降级保存**：点【保存】时，见 §4 硬规则第 2 条（4 项判定）

**FR-004 重新解析**：收件箱单条【✦ 解析这一条】或一键全部；**人工改过的重要/紧急不被覆盖**

**FR-023 字段来源**：**备注 = 用户原话**（逐字保留）；标题/时间/重要/紧急/归属/分类来自解析或手填；未解析时这 6 项全空，列表用**备注前 12 字**当占位标题

### 模块 B · 查看与优先级

**FR-005 基础管理**
1. 编辑 / 软删除（进回收站）/ 标完成 / 置顶
2. **点条目任意位置 = 进详情；点最左边小圆圈 = 标完成且不跳转** —— 两个热区分开
3. **标记完成后不消失**：整条转灰（含象限色条）、标题加删除线、**排到当日最下方**
4. **完成时刻记真实系统时间**（补做旧事时能看到"其实是今天才做完的"）

**FR-006 四象限与排序**（见 §4 硬规则第 1、3 条）

**FR-007 双域**：工作域冷蓝 `#2563EB` / 生活域暖珊瑚 `#F2784B`；两域数据**互不混入**；切换器在 ①② 栏常驻可切，第 ③ 栏灰色静态不可切

**FR-009 逾期**：逾期未完成进"逾期专区"置顶高亮，显示"逾期 N 天"；**逾期不改变象限颜色**（灰的还是灰）

**FR-010 今日视图与收件箱**
1. 第 ① 栏显示：逾期 + 今天（更远日期去日历看）
2. **取消 ≤10 条折叠，放不下可以下滑**
3. 收件箱是**跨域暂存区**：两域右下角各一个入口，**进的是同一个**；按钮底色随域变，红角标显示待整理条数

### 模块 C · 分类（FR-008）

1. 预置 8 个分类（见模块 E 验收 4）；可新建并指定**名称 / 颜色 / 符号**
2. 符号用**具象 emoji**（💼📝🖊️🧾📊🏠🛒🚗💰⏰…），不用 ●▲■◆ 这类抽象形状
3. 分类**不可跨域**（工作分类不出现在生活域的选择列表里）
4. **删除分类不删待办，改为「未分类」**（不进收件箱）
5. 支持**长按拖动排序**，顺序在选择分类时同样体现
6. 颜色作用在「淡色底衬 14% + 左侧 3px 实心竖条」上（emoji 是彩色字形，染不动）

### 模块 D · 导航与日历

**FR-011 快记入口**：手机上**没有悬浮 + 号**，点底部「记一笔」栏即自动聚焦输入框
**FR-012 语音入口**：不设麦克风按钮，语音走**系统输入法自带麦克风**（0 成本）
**FR-021 底部三栏**：① 记一笔（默认首屏）② 日历 ③ 我的；切栏时**当前域保持不变**
**FR-022 日历**
1. 按月展示，**可左右翻月**，今天有明确标记
2. 日期格显示 `3●2○`（数字 9px / 圈 6px）：● 已完成、○ 未完成
3. 当天有逾期 → **红色下划线**；这天有复盘 → 灰底色
4. 点某天 → 展开当天明细；**逾期项只挂在它原定那天**，不跟着跑到未来每一天
5. 明细里**只显示当前域**的事项

## 4. 硬规则清单（单一事实来源，冲突时以此为准）

| # | 规则 | 说明 |
|---|---|---|
| **1** | **排序：置顶 → 逾期组（组内按象限）→ 正常四象限 → 已完成沉底** | 逾期是"漏了"，比象限更该先看；逾期**组内部**仍按 ①②③④ 排 |
| **2** | **入箱判定只看 4 项**：标题 / 完成时间 / 轻重缓急 / 归属 —— **全填才出收件箱**，缺任一项即进箱 | **分类是选填项、不参与判定**，不填就是「未分类」，不算空缺 |
| **3** | **轻重缓急：存两个字段、显示一个选择器** | 存储层**始终是 `是否重要` / `是否紧急` 两个三态字段**（`null` = 未判断）；界面合并为**四象限选择器**（五态）。**不得因为 UI 合并就把库里也合并** |
| **4** | **列表不显示象限文字，选择器内必须显示** | 列表/日历只用颜色；四象限选择器内部**必须显示**"马上做/计划做/快速处理/有空再说"，否则不知道在选什么 |
| **5** | **人工决定不被覆盖（含批量）** | 手动改过的字段，重新解析不得覆盖；收件箱「一键全部重新解析」**逐字段判断**，改过的跳过 |
| **6** | **首屏不折叠**，放不下的条目下滑 | 原"≤10 条其余折叠"作废 |
| **7** | **A2 的「归属」只改这一条的归属**，不切整个 App 的域 | 换域时清空该条分类（分类不可跨域） |
| **8** | **备注 = 用户原话**，逐字保留，AI 不改写 | 未解析时它是唯一有内容的字段 |
| **9** | **完成时刻取真实系统时间** | 不再取硬编码日期 |
| **10** | **删除分类 → 待办改为未分类**，不进收件箱 | 与"删除不删待办"配套 |

## 5. 数据结构

### todos（待办）

| 字段 | 含义 | 必填 |
|---|---|---|
| id | 唯一标识 | 必填 |
| title | 标题（解析前为空，列表用备注前 12 字占位） | 必填 |
| domain | 归属域：`work` / `life`；**未解析进收件箱时为 `null`** | 必填 |
| cat | 所属分类，**可选**（不填 = 未分类） | 可选 |
| **imp** | 是否重要：**三态** `null` / `true` / `false` | 可选 |
| **urg** | 是否紧急：**三态** `null` / `true` / `false` | 可选 |
| **manual** | `{imp,urg}` —— 记录哪些是人工改过的（重新解析不得覆盖） | 可选 |
| due / time | 截止时间 / 具体时间。**只用于日历排布与逾期**，不参与象限计算 | 可选 |
| pinned | 置顶（永远排最前） | 可选 |
| done / doneAt | 是否完成 / **真实完成时刻** | 必填 / 可选 |
| remark | **= 用户原话**，逐字保留 | 可选 |
| inbox | 是否在收件箱（未解析） | 必填 |
| deleted | 软删除标记 | 必填 |
| **createdAt / updatedAt / source / parsed** | 创建时间 / 最后修改（冲突时以它为准）/ 来源 / 是否已解析 | 必填 |

**关键**：**四象限不落库**，每次由 `imp × urg` 实时算出；改任一标记，象限立刻跟着变。

### categories（分类）
分类名 / 所属域（不可跨域）/ 颜色 / 符号 / 排序

### daily_reviews（每日复盘）
**M1 不生成任何内容**（空壳）。M2 再启用：复盘日期 + 工作生活合并的一句话 + 统计 + 生成时间。

## 6. 接口契约（换实现不改调用方）

这两条是 M1 能快的关键。**换真 AI、换存储、加云同步，都只改函数内部。**

```js
/* ① 存储层：唯一负责读写 */
DB.load()  → {todos, CATS, CAT_STYLE, reviews} | null
DB.save()  → 把 {todos, CATS, CAT_STYLE, reviews} 写进 localStorage

/* ② 解析服务：输入原话，输出 6 字段 */
doParse(原话) → {title, due, time, dueText, imp, urg, cat, domain}
```

M1 的 `doParse` 用本地规则实现；**换成真大模型时，只要返回值结构不变，界面与所有调用方一行都不用改**。

## 8. M1 完成判据（逐条可验）

1. 断网状态下记一条 → 保存
2. **关掉浏览器 → 重新打开 → 那条还在**（FR-025 最关键的一条）
3. 能改标题/时间/轻重缓急/归属/分类，改完刷新仍在
4. **点小圆圈勾完成** → 条目转灰、沉底、显示真实完成时刻 → 刷新仍在
5. 日历能**翻到下个月**，点某天能看到当天明细
6. 首屏能**下滑**看到全部当日条目
7. 收件箱里 3 条待整理，填全 4 项后点【保存】→ 归入某域、离开收件箱
8. 生活域与工作域数据**互不混入**
