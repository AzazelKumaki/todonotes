## 1. 当前基底：V0.1 是什么

**一句话**：能真用起来的本地待办 App —— 记一条、关掉再打开还在、能改能勾、日历能翻月。

**V0.1 已完成的四条地基**（V0.2 全部继承，不要重做）：

| 地基 | 现状 |
|---|---|
| **本地数据存储**（FR-025） | `DB` 模块用 localStorage，KEY = `todo.v0.1`；`render()` 里落盘；启动先读本机、读不到才用种子 |
| **数据模型** | 字段已补全：`createdAt / updatedAt / source / manual / parsed`；`imp` / `urg` 是**三态**（`null` = 未判断） |
| **规则版解析** | `doParse()` 本地关键词 + 日期解析，**不联网、不要 Key** |
| **四象限选择器** | 界面合并成一个选择器，存储仍是 `imp` / `urg` 两个字段 |

**V0.1 明确没做**（V0.2 / V0.3 的活）：真 AI · 每日复盘 · 导出备份 · 本地自动备份 · APK · 云同步 · 循环安排 · P1/P2 增强。

## 2. 必须继承的硬规则（不推翻，冲突时以此为准）

| # | 规则 |
|---|---|
| **1** | **排序**：置顶 → **逾期组（组内按象限）** → 正常四象限 → 已完成沉底。逾期是"漏了"，比象限更该先看 |
| **2** | **入箱判定只看 4 项**：标题 / 完成时间 / 轻重缓急 / 归属，全填才出收件箱。**分类是选填项、不参与判定**（不填 = 未分类，不算空缺） |
| **3** | **轻重缓急：存两个、显示一个**。存储层**永远是 `imp` / `urg` 两个三态字段**；界面是四象限选择器（五态）。**不得因为 UI 合并就把库里也合并** —— 排序、象限推导、复盘统计都依赖这两个字段 |
| **4** | **列表不显示象限文字，选择器内必须显示**。列表/日历只用颜色；选择器内部必须写"马上做/计划做/快速处理/有空再说" |
| **5** | **人工决定不被覆盖（含批量）**：手动改过的字段，重新解析不得覆盖；批量重解析要**逐字段**判断 |
| **6** | **首屏不折叠**，放不下可下滑 |
| **7** | **A2 的「归属」只改这一条**，不切整个 App 的域；换域时清空该条分类 |
| **8** | **备注 = 用户原话**，逐字保留，AI 不改写；未解析时它是唯一有内容的字段 |
| **9** | **完成时刻取真实系统时间**；**四象限不落库**，实时由 `imp × urg` 算出 |
| **10** | **删除分类 → 待办改为未分类**，不进收件箱 |

### 两个接口契约（换实现不改调用方）

```js
/* ① 存储层 —— 唯一负责读写，换 IndexedDB / 加云同步只改这里 */
DB.load() → {todos, CATS, CAT_STYLE, reviews} | null
DB.save() → 写入 localStorage

/* ② 解析服务 —— M2 换成真 AI 时，只换 doParse 内部，返回结构不变 */
doParse(原话) → {title, due, time, dueText, imp, urg, cat, domain}
```

> **V0.2 最重要的一条约束**：接真 AI 时**只改 `doParse()` 内部**，返回值结构一个字都不要动。
> 这样解析面板、保存逻辑、收件箱、排序全部不用改。

### 3.2 【FR-001】解析升级为真 AI

只改 `doParse()` 内部，契约不变。

| 验收 | 内容 |
|---|---|
| 1 | 「明天下午3点前把季度报表交给王总，这个挺重要的」→ 标题=把季度报表交给王总；时间=次日 15:00；**重要=是 / 紧急=否**；域=工作 |
| 2 | 「客户那边催着要报价，尽快发过去」→ **重要=否 / 紧急=是**（说了急没说重要） |
| 3 | 「有空的时候去交一下电费」→ 时间=空；重要=否；紧急=否；域=生活 |
| 4 | **未提及轻重缓急时一律为"否"**，并提示"没听出轻重缓急，点这里标一下"——**出现 1 次擅自标为"重要"即判不通过**（红线 G5） |
| 5 | **仅凭"截止日期很近"不得推断为紧急** |
| 6 | 请求**必须携带当前日期时间**，否则"明天""下周三"会算错（10 条含相对时间样本，正确率 ≥ 90%） |
| 7 | **AI 只能从已有分类里挑**，不得自造分类名 |
| 8 | **响应时间 > 3 秒自动降级**：原话存进收件箱，界面不卡死、不报错弹窗 |
| 9 | 从"点开快记"到"保存成功" ≤ 8 秒 |

### 3.3 【FR-016】每日复盘自动生成

**复盘是全天跨域合并的一条**：AI 同时读工作 + 生活两边当天数据，生成**一句话**；两个域看到的**逐字相同**。

| 验收 | 内容 |
|---|---|
| 1 | 打开应用时，若"上一天"还没有复盘**且昨天有动静** → 自动生成，**存进日历该日期**（点那天才看到，不主动弹） |
| 2 | 一天内反复打开 → **只生成一次**，不重复不覆盖 |
| 3 | 连续 10 天未打开 → 自动回溯补**最近 7 天**（更早不自动生成，可手动补） |
| 4 | 当天**完全没动静**（0 完成、0 新增、0 逾期处理）→ **不生成**，也不留空白记录 |
| 5 | AI 失败 / 断网 / 超额度 → 标记"待生成"，下次打开自动重试，**不弹错误打扰用户** |
| 6 | 生成中途退出 → 下次打开重新检查，不丢不重 |
| 7 | **不做弹出卡片**：复盘展示在**日历该日期的明细区** |
| 8 | 日历上已有复盘的日期用**中性灰底**标示（不用圆点，圆点让给逾期） |
| 9 | 复盘归属"**上一天**"，不是今天 |
| 10 | **生成后锁定**：后来补记、补完成**不改写**旧文案；只有用户点【重新生成】才重算 |
| 11 | 卡片显示**生成时间**（如「生成于 10-16 09:41」）+【重新生成】按钮 |

## 7. 开发约定

**代码现状**：`prototype/index.html` 单文件（无框架、无构建），顺序为
数据层 → 存储层 `DB` → 工具 → 视图函数（`noteHTML / calendarHTML / meHTML / inboxHTML / detailHTML / …`）→ 事件委托。

**改代码时**：
1. **不要动 `DB` 的接口**，要加持久化字段直接往 `T()` 里加
2. **不要动 `doParse()` 的返回结构**，接真 AI 只换函数体
3. **`render()` 开头有 `DB.save()`** —— 任何改动都会自动落盘，不用手动调
4. **所有交互走事件委托**（`data-act`），新增按钮只需加 `data-act` + 一个分支
