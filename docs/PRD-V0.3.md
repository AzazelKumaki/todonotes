## 1. 背景与目标

### 1.1 背景
V0.2 之后，这台 App 已经"能记、能想、能备份"，但**数据是孤立的**：
电脑记一条，手机看不到；手机改了分类，电脑还是旧的。备份只能靠手动导出 JSON 再导入。

### 1.2 V0.3 的三条硬指标
1. **跨设备看见**：三台设备（电脑网页 / 手机 / 平板）打开就是同一份数据。
2. **不用点按钮**：改动后自动同步，断网时先记本机，联网后自动补传，不丢不重。
3. **同步失败不打扰**：状态只在「我的」页一行小字里体现，不弹错误框、不卡界面。

### 1.3 本地优先（本版产品底线，不可让步）

> 用户明确要求：**App 必须离线能用，网页版必须双击就能用。云同步是锦上添花，不是使用前提。**

| # | 底线 |
|---|---|
| 1 | **APK 保持本地壳**：网页代码打包在 App 里，断网照样能记、能改、能看 |
| 2 | **网页版双击 `index.html` 即可用**，不要求挂网站、不要求起本地服务 |
| 3 | 云同步**只能在这种形式下工作**：App 里填「服务地址 + 密钥 + 同步口令」，即标准的"自带钥匙"模式 |
| 4 | 云服务不可用（没配 / 断网 / 后端停了）时，**App 一切照常，只是不同步**，不弹错、不卡死 |

**推论**：能不能同步，取决于**选哪家后端**——凡是"不认访问来源"的后端都能在本机形态下用；凡是把密钥跟某个网址绑定的（WorkBuddy 内置通道就是这种），本机形态就一定用不了。详见 §4.1。

### 1.4 明确不做（避免范围蔓延）
| 不做 | 原因 |
|---|---|
| 多人协作 / 共享清单 | 单人自用，引入协作会牵扯权限与冲突 UI |
| 账号注册体系（用户名+密码） | 已拍板：用同步口令，不为同步造一个会员系统 |
| 云端存 AI Key / 云密钥 | 硬规则 12 |
| 云端图片附件 | 背景图暂存本机，附件属 V0.4 |
| 端到端加密（默认） | 见 §11 Q3，作为可选增强项 |

## 4. 云服务方案（本版核心）

### 4.1 先讲清楚一件事：为什么有的云能用、有的不能用

浏览器每发一个请求，都会附上一句"我是从哪儿来的"（来源 Origin），**服务端可以选择"认不认这个来源"**：

| 打开方式 | 浏览器报给服务器的来源 |
|---|---|
| 发布后的网址 `https://xxx.workbuddy.link` | `https://xxx.workbuddy.link` —— 一个**正经网址**，能认 |
| 双击打开的本地文件 | `file://` —— 服务器收到的是 `null`，**没法认** |
| APK 里内置的页面 | `file://android_asset/...` —— 同上，**没法认** |

于是后端分两种作风：

| 后端作风 | 做法 | 本机形态能用吗 |
|---|---|---|
| **不认来源型**（返回 `Access-Control-Allow-Origin: *`）| 谁来都答应，安全交给"你有没有拿对钥匙（Key）" | ✅ **能用** |
| **认来源型**（把密钥跟某个网址绑死）| 只有从这个网址来的请求才处理 | ❌ 用不了 |

**WorkBuddy 内置通道属于第二种** —— 这是它有意为之的安全设计：那把 `publishableKey` 写在前端谁都能看见，如果不绑定来源，别人把你的 key 抄到自己的网页上，就能刷你的额度、翻你的数据库。所以它把"钥匙 + 门牌号"绑在一起校验。**这不是限制你，是保护你的额度不被人白嫖。**

而你想要的那种"填个地址 + Key 就能用"的云服务，绝大多数是**第一种**：Supabase 的 API 网关默认就允许任意来源，并允许 `apikey` / `authorization` 这类自定义头。

**本机实测（2026-10-16，无头 Chrome 直接打开本地 `file://` 探针）**

| 检查项 | 实测结果 |
|---|---|
| 页面自己的来源 | `file://`（服务器侧看到 `null`） |
| `isSecureContext` | `true` |
| `crypto.subtle`（做口令加密用） | ✅ 可用 |
| 普通跨域请求 | ✅ HTTP 200，读到数据 |
| **带自定义 Key 头的跨域请求** | ✅ **HTTP 200** |

**结论：「双击打开 + 填地址 + 填 Key」这条路完全走得通。** 顺带说明：本机形态下也能做本地加密（见 §11 Q3）。

> 之前的实现已经踩过同样的路：DeepSeek 允许网页直连（它的跨域头回显任意来源），所以 `file://` 下 AI 解析照常工作；Kimi 不给跨域许可，浏览器里就必失败。**同一个道理。**

### 4.2 两条通道，本版选A，B 留作可选项

| | **A · 自带后端（本版主线）** | **B · WorkBuddy 内置通道（可选）** |
|---|---|---|
| 用户要做什么 | 去后端服务商拿一个「地址 + 密钥」，连同**同步口令**填进 App | 什么都不填，只用同步口令 |
| 网页**双击打开** | ✅ | ❌ |
| **APK 本地壳** | ✅ | ❌ |
| 发布成网址以后 | ✅ | ✅ |
| 需要注册账号吗 | 需要一个后端服务（有免费额度），**App 本身不用登录** | 不需要 |
| 顺带白嫖 | 无 | 内置免密钥大模型额度 |
| 代价 | 多一步：注册后端 + 新建一张表 | App 必须发布到网上，本机形态没份 |

**本版主线 = A**（符合"本地优先"底线）；B 保留为**可选实现**，将来发布网页版后可运行时切换，且**不阻塞任何本地功能**。

### 4.2.1 先别注册：用自带的本地服务器把链路跑通

仓库里带了一个**零依赖的本地同步服务器**（`tools/sync-server.js`，双击 `tools/start-sync-server.bat` 就跑），
它实现了后端协议的最小子集，让你**不用注册任何账号**就能把"配置 → 测试 → 推 → 拉 → 冲突"整条链路试一遍。
换成 Supabase 时，App 里改的只是「地址」和「密钥」两栏，代码一行不动。

> 它只是个试用品，只跑在你自己电脑上，**别当正式的云用**。

### 4.3 通道 A 推荐后端：Supabase（免费额度够个人用）

去 Supabase 建一个免费项目，拿到两样东西：**Project URL** 和 **anon public key**，在 App 的「我的 → 云同步」里填进去，再填一个自己想好的**同步口令**。不需要注册账号、不需要邮箱验证、不需要登录。

| 为什么它能在本机形态下工作 | 说明 |
|---|---|
| 网关默认允许任意来源 | `Access-Control-Allow-Origin: *`，且允许 `apikey` / `authorization` 自定义头 |
| 安全不靠认来源 | 靠「钥匙 + 行级策略（RLS）」，这正是我们要的姿势 |
| 与我们已有的做法一致 | 跟 DeepSeek 那种"填地址 + Key"完全同构 |

**两条必须提醒的（选型前以官网当前政策为准）**
- 免费额度对单人待办绰绰有余，但**长期不活动的项目可能被暂停**，需要去后台点一下恢复。
- anon key 是设计成"可以公开的那把钥匙"，**必须**配合行级策略使用；**绝对不要把最高权限的那把 key 填进 App**（APK 可以被反编译，前端不存在真正的秘密保险箱）。

备选自建：自己跑一套 PostgREST / NAS / 任何"给地址 + Key + 允许跨域"的后端都行，App 里预留「自定义」一档。

**为什么推荐用 Key 而不是账号密码**：账号密码一旦泄露，别人能进后台改你的库；给 App 的 Key 可以只开放"读写这一张表"的权限。真要用密码，也应该是"密码换 token"的方式。

### 4.4 统一适配层（换后端不改调用方）

无论用哪家后端，`CLOUD` 只暴露三个动作，上层 Sync 引擎一行不改：

```js
CLOUD.init(cfg)        // cfg.kind = 'supabase' | 'postgrest' | 'builtin'
CLOUD.pull(spaceId)    // → {payload, updatedAt} | null
CLOUD.push(spaceId, payload, baseUpdatedAt)
                       // → {ok:true, updatedAt} | {ok:false, conflict:true, remoteUpdatedAt}
```

- **A 方案用 `fetch` 直连 REST**（带 `apikey` / `authorization` 头），**不引入任何 SDK**，保持单文件、零依赖。
- **B 方案用 `@tencent-ai/workbuddy-cloud-sdk`（CDN）**：`endpoint` 与 `publishableKey` **只能来自 `publicConfig`**，禁止硬编码、禁止从 `location` 推导、禁止手写 `/.cloud/**` 的 fetch。
- 任何一家失败 → 返回 `{ok:false, reason}`，上层一律降级为本机 mode，**不弹错、不阻塞**（硬规则 13）。

### 4.5 云端只存一行：表结构与隔离

> 思路：**云端只存"整包快照"一行**，不做逐条待办的云端合并。
> 好处：与本地 `DB.load()/save()` 契约完全一致，同步逻辑极简；代价是多设备同时编辑按"最后写入胜出"（单人轮流使用够用，见 §10 R1）。

```sql
create table if not exists todo_state (
  space_id    text primary key,              /* 由同步口令派生，256 位，不可猜 */
  payload     jsonb not null,                /* {v,todos,CATS,CAT_STYLE,reviews} */
  updated_at  timestamptz not null default now(),
  device_id   text,
  app_ver     text
);
```
```sql
alter table todo_state enable row level security;
```
```sql
drop policy if exists todo_state_space on todo_state;
create policy todo_state_space on todo_state for all
  to anon using (true) with check (true);
```

**要点**
- `space_id = base64url(PBKDF2-SHA256(同步口令, 固定 salt, 100000 次)[0..31])` —— **口令本身永远不上传**。
- 隔离完全依赖**不可猜的 space_id**：本质就是"知道口令，才找得到这份数据"，跟网盘分享链接一个道理。
- `payload` 与导出 JSON 同构（同一份 `v:2` 包）→ 同步与导入**复用同一套合并函数**。
- 想再加一道锁：把 `payload` 用口令派生的密钥在本地加密后再上传（§11 Q3），这样连数据库管理员也看不懂内容。

### 4.6 免密钥大模型（内置通道专属）

AI 服务商现在有五档：`WorkBuddy 内置` / `DeepSeek` / `Kimi` / `OpenAI` / `自定义`。
选「内置」时**不用填 Key**，但**同样受来源限制**：只有发布成网址后才能用；本机形态下这一档自动标注"需要发布后使用"，不隐藏、不报错。

技术实现要点（将来做 B 方案时逐条对照）：
1. `stream` **必须为 `true`**（不支持非流式，否则 SDK 在发请求前就抛 `request_stream_required`）。
2. **首条消息必须是 `system`**（直接用 `PROMPTS.parse` / `PROMPTS.review`），否则调用失败。
3. 一次性调用（解析、复盘）**不要传 `conversationId`**；它只是路由关联 ID，不会让模型记住上下文。
4. 错误按 `error.code` 前缀分支：`request_` 不重试 / `auth_` 提示来源不匹配 / `quota_` 额度用尽 / `gateway_`、`model_` 给【重新生成】/ `internal_` 显示 `requestId`。

**本机形态的 AI 不受影响** —— 继续走 DeepSeek / Kimi / OpenAI / 自定义四档（DeepSeek 实测允许网页直连）。

### 4.7 三端可用矩阵（界面口径以此为据）

| 功能 | 网页双击打开 | APK 本地壳 | 发布后的网址 |
|---|---|---|---|
| 记录 / 修改 / 查看 / 导出 / 备份 | ✅ | ✅ | ✅ |
| 第三方 AI（DeepSeek 等） | ✅ | ✅ | ✅ |
| **云同步 · 通道 A（填地址+Key）** | ✅ | ✅ | ✅ |
| 云同步 · 通道 B（内置） | ❌ | ❌ | ✅ |
| 内置 AI（免密钥） | ❌ | ❌ | ✅ |

不可用的环境**不报错、不置灰任何功能**，只在「我的 → 云同步」用一行小字说明原因与出路（例："当前是本地打开，内置通道用不了；想用请改用第三方云填地址+Key，或把这个 App 发布成网址"）。

## 6. 分步开发清单（按依赖顺序，每步可单独验证）

### S1 · 后端准备（在控制台，不动代码）　复杂度：低
1. 按 §11 Q1 选定后端（推荐 Supabase 免费项目），拿到 **服务地址 + anon key**。
2. 在它的 SQL 编辑器里跑 §4.5 的三段脚本（建表 → 开行级安全 → 建策略），一次贴一段。
3. 用浏览器或命令行验证：带 `apikey` 头的读写各成功一次 **且不报错**。

### S2 · 云同步主通道（通道 A）　复杂度：高
1. 写 `CLOUD` 适配层：`kind='supabase'|'postgrest'`，只用 `fetch`，**不引入任何 SDK**，保持单文件零依赖。
2. 写 `SYNC` 引擎：`pull`（按 `space_id` 取一行，云端 `updated_at` 新于本地基线才合并）/ `push`（整包 upsert，带 `Prefer: resolution=merge-duplicates` 或等价写法）/ 防抖 800ms。
3. 冲突：双方都有改动 → 弹窗二选一（本机 / 云端）；自动合并仍以 `updatedAt` 更晚为准。
4. 离线：`online` 事件 + 轮询补传；写操作返回空结果要明确提示，**不静默当成功**。
5. 成功后 `BAK.snapshot()`；`SYNC.state()` 给 UI 一行小字。

### S3 · 配置页与配置码　复杂度：中
1. 「我的 → 云同步」：服务地址 / 密钥 / 同步口令 三项输入 +【测试连接】+【保存】+【断开】。
2. 测试数据必须来自**一次真实读写**（不是 ping），通过才允许保存。
3. 【导出配置码】/【导入配置码】+ 二维码；导出弹窗明示"等于钥匙，别外传"。
4. 密钥落盘沿用现有混淆 `obf()`，**不进数据备份文件**。

### S4 · APK 与在线更新　复杂度：中
1. **APK 保持本地壳**（已拍板），MainActivity 不动。
2. `version.json` 放 §11 Q4 定下的地址，字段 `{version, apkUrl, notes}`。
3. 【检查更新】真去查一次：已是最新显示版本号与检查时间；有新版本显示版本号 +【下载并安装】，走 MediaStore 落盘后引导安装。

### S5 · 内置通道与内置 AI（可选，前四步做完再做）　复杂度：中
1. 通道 B：`inspect` → `activate`（界面弹窗确认）→ 用 `publicConfig` 实现第二种 `CLOUD` 后端；`endpoint` 与 `publishableKey` 只从 `publicConfig` 取，**禁止硬编码**。
2. 内置 AI：`cloud.llm.models.list()` 拉列表 → `doParseAsync` 增加内置分支（`stream:true` + `messages[0]=system`）→ 复盘走 `PROMPTS.review`。
3. 频率限制：解析 3 秒内最多 1 次，复盘每天最多 2 次。
4. 本机形态下这两项**自动跳过**，界面给一行说明（§4.7）。

### S6 · 两处小修　复杂度：低
回收站 30 天清理（FR-311）、自定义背景图（FR-312）。

## 9. 开发约定与踩过的坑

**沿用**
1. 不要动 `DB` / `doParse` 的接口，要加字段直接往 `T()` 里加。
2. `render()` 开头有 `DB.save()` —— 改动会自动落盘。
3. 所有交互走事件委托（`data-act`），点击处理是具名函数 `handleAct(e)`。
4. 改完代码必跑测试：`cd tests && node smoke.js` / `ai-smoke.js` / `inbox-save.js` / `ai-models.js` / `ui-actions.js` / `ui-fixes.js` / `manual-guard.js`。
   新增函数要手动加进 `tests/harness.js` 的 `globalThis.__app` 导出列表。
5. 改 CSS 后跑花括号平衡校验（曾因残留孤儿 `}` 导致弹窗错位、页面错乱）。
6. 视觉问题用无头 Chrome 验证：`chrome.exe --headless=new --screenshot=out.png --virtual-time-budget=2500 file:///探针.html`；
   探针 = index.html 副本 + 注入脚本，**每次都要从最新 index.html 重新生成**。
7. APK 打包 `android/build-apk.bat`：`copyWeb` 路径必须写 `../../prototype/index.html`；settings.gradle 用 `PREFER_SETTINGS`；`daiban.keystore` 不能丢。
8. AI 连接实测：DeepSeek 允许网页直连、地址带不带 `/v1` 都通；Kimi 在浏览器里必失败；`fetch` 抛 `TypeError` 一律翻成人话。

**云同步新增（通道 A 为主）**
9. **保持单文件零依赖**：通道 A 一律用 `fetch` 直连 REST，**不引入任何 SDK、不加 npm、不拆分文件**。
10. **所有云请求必须有超时（建议 5 秒）+ try/catch**，失败一律返回 `{ok:false, reason}`，由上层降级；**不许让同步把 UI 卡住**。
11. `fetch` 抛 `TypeError` 一律翻成人话（"请求没发出去，多半是对方不给跨域或网断了"）。
12. **写操作返回空结果 = 没写进去**，必须显式提示，不能当成功。
13. 密钥、口令的明文**不进日志、不进数据备份、不进回复**；`console` 里也不许打。
14. 新增的云模块（`CLOUD` / `SYNC`）要加进 `tests/harness.js` 的导出列表，并补 mock 测试：连通、冲突取新、离线补传、401/超时、降级路径。
15. **本机形态（`file://`）必须逐项实测**：`isSecureContext` / `crypto.subtle` / 带自定义头的跨域请求 —— 2026-10-16 实测三项均通过（见 §4.1）。
16. 将来做通道 B 时：`endpoint` 与 `publishableKey` 只从 `publicConfig` 取，**禁止硬编码**；禁止手写 `/.cloud/**` 的 fetch；LLM 调用必须 `stream:true` 且 `messages[0]` 是 system。
17. **密钥里不能有中文/全角符号** —— HTTP 头放不下它，会被浏览器直接掐掉；不前置校验的话，错误会被误报成"对方不给跨域"，把人带沟里（已在 `CLOUD.hdr` 拦成 `KEYCHAR`）。
18. **连内网地址（`127.0.0.1` / `192.168.x.x`）时，服务端必须额外回 `Access-Control-Allow-Private-Network: true`** —— 浏览器的"本地网络保护"会先发预检问一句，不点头请求就发不出去。换成公网 HTTPS 地址（Supabase）没这一步。`tools/sync-server.js` 已经处理。
19. 调试浏览器链路用 **CDP**（`--remote-debugging-port` + WebSocket 读 DOM）。`--dump-dom` 会在异步跑完前就把页面吐出来，配上 `--virtual-time-budget` 还会把 `setTimeout` 快进、导致请求被超时掐断，**两者都不可靠**。

## 10. 风险与取舍

| # | 风险 | 取舍 |
|---|---|---|
| R1 | 整包快照 = 最后写入胜出，多设备同时编辑会互相覆盖 | **接受**。单人轮流使用场景极少冲突；冲突时弹窗让用户选（硬规则 5 同口径）。逐字段合并留到 V0.4 |
| R2 | 后端的 Key 写在 App 里，理论上能被反编译看到 | **接受但降险**：只用权限最小的那把 anon key + 行级策略 + 不可猜的 `space_id`；可选再叠一层本地加密（Q3）。前端本来就没有真正的保险箱，这与现有 AI Key 的处理口径一致 |
| R3 | 免费后端长期不动可能被暂停 | 界面提示"云端没响应，数据还在本机"并给出去后台恢复的指引；不阻塞使用 |
| R4 | 换后端厂商成本 | `CLOUD` 适配层把差异收敛在三个方法里，换厂商只改一个文件内的分支 |
| R5 | 同步到一半改数据 | push 防抖 800ms，push 期间不阻塞 UI；失败进队列下次再试 |
| R6 | 用户忘了同步口令 | **无找回通道**（云端没有口令）。配置码 + 本地快照是唯一备份，UI 必须反复提醒自己存好 |
