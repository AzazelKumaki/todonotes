## 3. 我建议的顺序（待你拍板）

先说判断依据：V0.5 解决的是**「手要少动几下」**（批量 + 自动续期）。下一版该解决的是
**「回头看得清楚」** —— 现在完成的事沉在当天底部，攒久了就只剩「沉下去」这一个去处，没有
「这周到底做了什么」的视角。

**方案甲 ·「看得更清楚」（推荐）**

| 阶段 | 做什么 | 理由 |
|---|---|---|
| S1 | FR-603 完成归档与回溯 | 补上最缺的「回看」视角，不碰解析也不碰数据结构 |
| S2 | FR-604 周报 / 月报 | 跟 S1 天然一对，共用素材，做完一起见效 |
| S3 | FR-605 完成统计与趋势 | 有了 S1/S2 的口径，图才有意义 |

**方案乙 ·「补完上次砍的两条」**

| 阶段 | 做什么 | 理由 |
|---|---|---|
| S1 | FR-601 一句话拆多条 | 记录入口更省事（要动解析契约，趁状态好做） |
| S2 | FR-602 子任务 | 动数据结构，放最后 |

**方案丙 · 混着来（一条省事 + 一条回看）**

`FR-601 拆多条 → FR-603 回看 → FR-604 周报 → FR-602 子任务`

> 我的倾向：**甲**。理由 —— 拆多条和子任务你已经在 V0.5 砍过一次，说明没那么疼；
> 而「这周做了什么」是每天都会碰到、现在完全没着落的事。

## 4. 三条细节（给排序最靠前的先写清楚）

### FR-603 · 完成归档与回溯

| 项 | 内容 |
|---|---|
| **入口** | 日历页加一个「回看」；或第 ③ 栏加一项（待定） |
| **界面** | 按完成日分组（周 / 月切换），每组显示条数 + 清单 |
| **口径** | 用 `doneAt`（真实完成时刻）分组，不是 `due`（原定日期）—— 跟现在「完成于 …」的口径一致 |
| **边界** | 已删除的（回收站里的）不算；已完成但原定在未来的，按**完成那天**算 |

**验收**：勾完 5 件事 → 回看页本周能看到这 5 件，分组在各自完成那天下面。

### FR-604 · 周报 / 月报

| 项 | 内容 |
|---|---|
| **触发** | 回看页上一个按钮；没配 AI 时用**规则版**汇总（照现有「当天总结」的做法） |
| **输出** | 一段话（不是表格）：做了多少、主要在哪个域、逾期几件 |
| **降级** | AI 没配 / 失败 → 规则版照样给得出，不卡不报错 |

### FR-601 · 一句话拆多条（若要做的）

| 项 | 内容 |
|---|---|
| **契约** | `doParse()` 保持返回**单条**不变；新增 `doParseMulti()` 返回数组 |
| **界面** | 检测到多件事 → 解析面板切成「多件事」视图，逐条列出，可单独删 / 改，底部【全部保存】 |
| **降级** | AI 没配 / 失败 → 规则版按连接词（`并 / 顺便 / 还有 / 、 / 然后`）切分；切不出来就退回单条 |

## 5. 硬约束（继承，别破）

1. **单文件**：`prototype/index.html`，零依赖、无构建、双击能用；APK 是 WebView 壳。
2. **AI 永远可以失败**：超时 / 未配 / 报错 → 退回规则版，结构不变，不卡不弹错。
3. **人工决定不被覆盖**：唯一入口 `applyParse()` + `keepManual()`（保护 7 个字段）。
4. **云服务只是锦上添花**：没配 / 断网 / 后端挂 → 一切照常，只不同步。
5. **排序口径**：置顶 → 逾期组（组内只按轻重缓急）→ 其余按时间先后 → 同一时间再按轻重缓急 → 已完成沉底。
6. **`file://` 下 IndexedDB 打不开**：存储仍走 localStorage，大块数据必须单独 key。
7. **界面不留说明小字**：只留「状态 / 安全 / 报错」，用法写进内容手册。
8. **电脑版与手机版共用一套 DOM**：新增界面必须同时过 900px 上下两档（断点见上一版 FR-500）。
