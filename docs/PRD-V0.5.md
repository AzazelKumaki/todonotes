## 1. 一句话

V0.4 把「记录—整理—同步—备份」这条链路做完整了。V0.5 不再扩地盘，只解决一件事：
**事多的时候，手要少动几下**。

## 2. 为什么是这四条

来源：上一版 §11.1 已经拍板（2026-10-19），顺序 **A → B → C → E**。

| # | 需求 | 一句话 | 排这个位置的理由 |
|---|---|---|---|
| A | **批量操作** | 长按进多选态：批量完成 / 改分类 / 顺延到明天 / 删除（进回收站） | 改动最小、天天用得上，先出成果 |
| B | **一句话拆多条** | 「明天交报表，顺便买牛奶」→ 拆成多条，可逐条确认再存 | 与现有解析强相关，接着 A 做最顺 |
| C | **重复待办补全** | 现有「循环安排」只能一次性排 3 次 → 补：**完成后自动续下一次**，规则可编辑 / 关闭 | 半成品补完，性价比高 |
| E | **子任务** | 一条拆成若干步骤，父任务显示 2/3，全勾完**提示**（不自动完成） | 动数据结构，放最后做，风险可控 |

**❌ 不做**：~~到期提醒（含应用内提醒）~~ —— 2026-10-19 已整个删除，不再安排（原因存档在 V0.4 §11.3）。

## 3. 需求细节

### FR-501 · 批量操作（A）

| 项 | 内容 |
|---|---|
| **入口** | 列表项**长按**进多选态（与分类管理现有的长按拖动不冲突：那里是「长按 + 拖动」，这里是「长按不动」） |
| **多选态** | 顶部出现一条操作条：`已选 N 条` + 【全选】+【取消】；底部固定四个动作 |
| **动作** | ① 标完成 / 取消完成　② 改分类（弹已有分类列表 + 「不分类」）　③ 顺延到明天（只改 `due`，不动 `time`）　④ 删除（**软删除进回收站**，可恢复） |
| **退出** | 【取消】/ 手机返回键 / 点操作条外的空白区 |
| **边界** | 已完成的条目也允许被选中；批量改分类时**跨域不生效**（分类挂域下，硬规则） |

**验收**：选 5 条点【顺延到明天】→ 5 条的 `due` 全部 +1 天、`time` 不变、`updatedAt` 刷新，同步后另一端一致。

### FR-502 · 一句话拆多条（B）

| 项 | 内容 |
|---|---|
| **触发** | 还是那个 ✦，但一句里出现「并 / 顺便 / 还有 / 、 / 然后」等多件事时，拆成多条 |
| **契约** | `doParse()` 保持返回**单条**不变（向后兼容）；另出 `doParseMulti()` 返回数组。解析面板检测到多件时**自动切多件事视图** |
| **界面** | 多件事视图下逐条列出（标题 + 时间 + 轻重缓急），**每条可单独删 / 改**；底部【全部保存】 |
| **降级** | AI 没配 / 失败 → 规则版按连接词切分；切不出来就退回单条（现状） |
| **保存** | 缺字段的按老规矩进收件箱，其余直接入列表 |

**验收**：「明天交报表，顺便买牛奶，还要给王总回电话」→ 拆出 3 条，删掉中间那条只存 2 条。

### FR-503 · 重复待办补全（C）

| 项 | 内容 |
|---|---|
| **现状** | 「循环安排」一次性排 3 次，`t.recur=true` 只是个标记，用完就没了 |
| **补什么** | ① 勾完一次 → **自动续下一次**（按原规则算下一个日期）　② 规则可编辑 / 暂停 / 关闭　③ 列表里这类条目标一个循环符号 |
| **数据结构** | `t.recur` 由布尔扩展成对象：`{mode:'week'|'month'|'every', wd?, md?, every?, time?, on:true}`。**老数据 `recur:true` 要能识别**（按一次性处理，不报错） |
| **边界** | 每月规则遇到 31 号 → 取当月最后一天（现有 `genRecur` 已这么处理，沿用）；续期时**不继承**已填的 `doneAt` |

**验收**：每周三的会 → 勾完成 → 自动出现下周三那条；关掉规则后不再续。

### FR-504 · 子任务（E）

| 项 | 内容 |
|---|---|
| **数据** | 条目加 `subs:[{id,title,done}]`（**数组**，保持单文件、不引依赖）；老数据没有这个字段 = 没有子任务 |
| **界面** | 详情页里单独一栏：可加 / 勾 / 删 / 改名字；列表条目副标题显示 `2/3` |
| **完成规则** | 子任务**全勾完只提示**（「三个步骤都做完了，要标完成吗？」），**不自动完成父任务** —— 最后那一下由人决定 |
| **排序** | 子任务按添加顺序，不做拖动排序（V0.5 不做） |
| **兼容** | 导出 JSON / CSV 要带上 `subs`（CSV 里合并成一列，用 `、` 分隔）；导入老版本文件（无 `subs`）不能报错 |

**验收**：建 3 个子任务勾完 → 出现提示而非自动完成；导出再导入，子任务还在。

## 4. 施工顺序（S1~S4）

| 阶段 | 做什么 | 复杂度 | 依赖 |
|---|---|---|---|
| **S1** | FR-501 批量操作 | 中 | 现有列表交互 |
| **S2** | FR-502 一句话拆多条 | 高（**契约要扩**） | 解析层 |
| **S3** | FR-503 重复待办补全 | 中 | `recur` 结构扩展 |
| **S4** | FR-504 子任务 | 高（**动数据结构**） | 导出 / 备份格式兼容 |

每做完一条就跑一遍全量测试 + 打一次 APK，不攒着。

## 5. 硬约束（继承，别破）

1. **单文件**：`prototype/index.html`，零依赖、无构建、双击能用；APK 是 WebView 壳。
2. **AI 永远可以失败**：超时 / 未配 / 报错 → 退回规则版，结构不变，不卡不弹错。
3. **人工决定不被覆盖**：唯一入口 `applyParse()` + `keepManual()`（保护 7 个字段）。
4. **云服务只是锦上添花**：没配 / 断网 / 后端挂 → 一切照常，只不同步。
5. **排序口径**：置顶 → 逾期组（组内只按轻重缓急）→ 其余按时间先后 → 同一时间再按轻重缓急 → 已完成沉底。
6. **`file://` 下 IndexedDB 打不开**（上一版 §8 坑 35 有实测证据），存储仍走 localStorage，大块数据必须单独 key。
7. **界面不留说明小字**：只留「状态 / 安全 / 报错」，用法写进内容手册。
